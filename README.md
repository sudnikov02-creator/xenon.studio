# xenon.studio

Персональная платформа фотографа: записи, клиенты, сообщения, маркетинг и аналитика — в одной спокойной
панели. Интерфейс на русском языке, светлая тема, синий акцент.

## Стек

| Слой | Технологии |
| --- | --- |
| Frontend | React 19, TypeScript, Vite 8, React Router 7, lucide-react, свои CSS-токены и компоненты |
| Backend | Node.js, Express 4, better-sqlite3 (WAL), cookie-сессии, bcryptjs |
| Realtime | Server-Sent Events (`/api/events`) — заявки, сообщения, бейджи, настройки |
| PWA | vite-plugin-pwa (Workbox), манифест, push-обработчик, офлайн-страница |
| Уведомления | web-push (VAPID), Telegram/email — в следующих этапах |

## Запуск

```bash
npm install
npm run dev        # API :3001 + Vite :5173
```

Откройте `http://localhost:5173`.

Демо-доступ (создаётся при первом запуске):

```
email:  studio@xenon.studio
пароль: xenon2026
```

Учётные данные подсказываются на экране входа. Отключить подсказку и демо-сид:

```bash
XENON_DEMO=0 XENON_SEED=0 npm run dev
```

### Другие команды

```bash
npm run typecheck   # проверка типов
npm run build       # production-сборка (dist/)
npm start           # Express отдаёт dist + API на PORT (по умолчанию 3001)
```

### Переменные окружения

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3001` | порт API/прод-сервера |
| `XENON_DATA_DIR` | `./data` | каталог базы SQLite |
| `XENON_DB` | `data/xenon.db` | путь к файлу базы |
| `XENON_SEED` | `1` | создание демо-студии при пустой базе |
| `XENON_DEMO` | `1` | показывать демо-доступ на экране входа |
| `XENON_VAPID_PUBLIC` / `XENON_VAPID_PRIVATE` | генерируются в БД | постоянные ключи push-уведомлений |
| `VERCEL` | — | автоматически выставляется Vercel: БД уезжает в `/tmp` |

База, сессии и VAPID-ключи создаются автоматически. Каталог `data/` в `.gitignore`.

## Прогресс по этапам

- **Этап 1 — готов:** инициализация, PWA, схема БД, авторизация фотографа, каркас панели
  (сайдбар с анимированными подменю, шапка, нижняя навигация, шторка «Ещё»), уведомления и тосты,
  живые бейджи, страницы 404 и истёкшей ссылки, профиль и смена пароля.
- **Этап 2 — готов:** дашборд с метриками (записи, доход, средний чек, новые клиенты — с трендом к
  прошлому месяцу и анимацией счётчика) и виджетами «Съёмки сегодня», «Заявки», «Календарь», «Доход по
  неделям»; drag-and-drop перестановка с «призраком» виджета и пунктирным плейсхолдером, перестановка
  из меню виджета; настройка видимости и порядка метрик и виджетов, параметры каждого виджета;
  подтверждение и отклонение заявки (с комментарием клиенту) прямо с дашборда; переключение месяца в
  мини-календаре; сохранение раскладки в настройках студии; счётчик заявок в сайдбаре и нижней
  навигации; обновление по SSE.
- **Этап 3 — готов:** услуги и пакеты (создание, редактирование, дублирование, удаление с проверкой
  вхождений в пакеты, сортировка и сдвиг, доп. опции с типами и ценами, валидация полей и 422-ошибки),
  рабочее расписание (часы по дням, перерывы, выходные, буфер, минимальный запас времени, горизонт
  записи, исключения по датам), переключатели и сохранение через `PATCH /api/settings`, публичный
  список услуг для формы записи, живое обновление по SSE.
- Этапы 4–16 — далее по плану (форма записи, записи, клиентская страница, статусы, CRM, чат,
  маркетинг, бонусы, автоматизация, календарь/аналитика, отзывы и лендинг, финал).

## API дашборда

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/dashboard` | метрики месяца, заявки в ожидании, съёмки сегодня, ближайшая съёмка, мини-календарь, доход по неделям |
| `GET` | `/api/dashboard/calendar?month=YYYY-MM` | счётчики и список съёмок другого месяца |
| `POST` | `/api/bookings/:id/accept` | подтвердить заявку (переводит в статус «Подтверждена», пишет событие, рассылает SSE) |
| `POST` | `/api/bookings/:id/decline` | отклонить заявку с комментарием клиенту (до 600 символов) |

## API услуг и расписания

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/services` | список услуг и пакетов с доп. опциями и количеством вхождений |
| `POST` | `/api/services` | создать услугу (или пакет при `kind: 'package'`) |
| `PATCH` | `/api/services/:id` | обновить услугу, пакет или доп. опцию |
| `DELETE` | `/api/services/:id` | мягкое удаление с проверкой пакетов |
| `POST` | `/api/services/reorder` | сохранить порядок карточек |
| `POST` | `/api/services/:id/shift` | сдвинуть карточку на шаг вверх/вниз |
| `POST` | `/api/services/:id/duplicate` | дублировать услугу или пакет |
| `GET` | `/api/public/services` | публичный список услуг для формы записи |
| `PATCH` | `/api/settings` | рабочее расписание, буферы, перерывы, выходные, горизонт записи |

## Деплой на Vercel

Репозиторий готов к деплою без ручных настроек: `vercel.json` задаёт сборку Vite, статику из `dist`
и единственную serverless-функцию `api/[...path].js`, которая отдаёт весь Express-API.

```bash
# локальная проверка serverless-сборки
npm run build && npx vercel dev
```

Что важно знать про запуск на Vercel:

- **База переезжает в `/tmp`.** В serverless-окружении `server/db.js` использует `/tmp/xenon-data`,
  поэтому демо-данные создаются заново после холодного старта. Для реальной работы нужна внешняя
  БД (Postgres/Neon) — это отдельный шаг.
- **SSE работает в пределах жизни функции.** Стрим живёт до `maxDuration` (60 с), затем браузер
  переподключается; на Vercel это демо-режим, на обычном Node-хостинге ограничения нет.
- **Push-уведомления** требуют постоянного VAPID-ключа — задайте `XENON_VAPID_PUBLIC`/`XENON_VAPID_PRIVATE`
  в переменных проекта, иначе ключи генерируются на каждый старт.
- Полноценный вариант (SQLite-файл, долгие SSE-соединения, фоновые задачи) — обычный Node-хостинг:
  `npm run build && npm start` за nginx.

## Заметки по архитектуре

- **Единственный пользователь.** Регистрация доступна только пока в базе нет аккаунта; клиенты
  взаимодействуют по индивидуальным ссылкам `/b/:code` и не имеют учётных записей.
- **Настройки студии** хранятся одной JSON-строкой и мгновенно применяются на клиенте: акцентный цвет,
  название, favicon, тема браузера. Изменения рассылаются по SSE.
- **Сессии** — httpOnly-cookie на 30 дней; пароль хранится bcrypt-хешем; вход ограничен rate-limit.
- **Realtime** — единый SSE-канал с heartbeat; бейджи непрочитанного обновляются автоматически.
- **PWA** — установка, push-handler, офлайн-страница; в dev service worker отключён, проверяйте на
  `npm run build && npm start`.
- **Раскладка дашборда** — объект в настройках: `{ metrics: Record<key, boolean>, widgets: [{ id,
  visible, config }] }`; порядок виджетов и их параметры сохраняются сразу, без кнопки «Сохранить».
- **Расписание** — единственный источник правды для слотов: `week[day] = { enabled, start, end,
  breaks[] }`, `exceptions[]` по датам, `bufferMin`, `noticeHours`, `horizonDays`. Перед сохранением
  расписание нормализуется и валидируется на сервере (невалидное — `422 invalid_schedule`).
